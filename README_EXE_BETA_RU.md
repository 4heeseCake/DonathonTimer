# Donathon Timer 0.9.4 Beta 3 — как получить установочный EXE

Это **проект для сборки в Windows** на основе стабильного 0.9.3.2. Сборка производится на настоящей Windows 10/11 x64 (либо в GitHub Actions на Windows runner). Запускать `run.bat` пользователям готового релиза **не нужно**.

## Что получат стримеры

- `DonathonTimer-0.9.4-beta3-Setup.exe` — обычный установщик для Windows с ярлыком и деинсталлятором, без запроса прав администратора.
- `DonathonTimer-0.9.4-beta3-Portable.zip` — portable-вариант (распаковать целиком и запустить EXE).
- Анализ речи — опциональная кнопка установки непосредственно внутри «Анализа». Дополнительный компонент подгружается только после согласия пользователя, отдельно от основного установщика.
- При первом распознавании речи отдельно загружается модель; собственно распознавание выполняется **после стрима**, на CPU максимум в два потока.

## Быстрее всего: GitHub Actions

1. Создай **публичный** репозиторий GitHub, например `username/donathon-timer`. GitHub не добавляет пользователей автоматически и не публикует ничего без твоего действия.
2. Загрузи **содержимое этой папки** в корень репозитория, включая `.github/workflows/windows-beta-release.yml` и `installer`.
3. Открой репозиторий → Settings → Actions → General → Workflow permissions. Включи разрешение Actions создавать релизы (Read and write permissions), если оно ещё не разрешено.
4. Открой вкладку Actions → **Build and publish Windows beta** → Run workflow → оставь `v0.9.4-beta3` → запусти.
5. Дождись успешного завершения. В разделе **Releases** автоматически появятся установщик, portable-архив, модуль речи и контрольные суммы.
6. Отправляй тестерам ссылку на релиз `https://github.com/username/donathon-timer/releases`. Для будущего сайта можно сделать кнопку «Скачать для Windows», ведущую на тот же релиз.

**Важно:** у GitHub Actions есть ограничения и тарификация в зависимости от плана и публичности репозитория; перед запуском проверь разрешения и условия своего аккаунта.

## Локальная сборка на твоём Windows

Понадобится:

- **Python 3.12 x64** (поставить галочку Add Python to PATH при установке);
- **Inno Setup 6**, официально: https://jrsoftware.org/isinfo.php;
- интернет для установки Python-зависимостей при сборке.

В PowerShell открой папку проекта и выполни:

```powershell
powershell -ExecutionPolicy Bypass -File .\buildtools\build-windows.ps1
```

Результаты будут в `release\`. Без `-Repo` / `-Tag` установщик и portable собираются, но **кнопка установки речи из опубликованного EXE не сможет скачать компонент**, пока не указан официальный GitHub Releases адрес.

Для полноценной сборки с ленивой установкой речи:

```powershell
powershell -ExecutionPolicy Bypass -File .\buildtools\build-windows.ps1 -Repo 'YOURNAME/REPO' -Tag 'v0.9.4-beta3'
```

После этого **все три файла** (`Setup.exe`, portable ZIP, `DonathonSpeech-...zip`) нужно опубликовать в *одном* GitHub Release с этим тегом. Манифест внутри EXE содержит контрольную сумму ZIP, поэтому заменять архив речи без повторной сборки основного приложения нельзя.

## Установка и обновление без потери данных

Установщик создаёт папку `%LOCALAPPDATA%\Programs\Donathon Timer`, а данные остаются отдельно в `%LOCALAPPDATA%\DonathonTimer`.

Перед первым тестом на всякий случай скопируй `%LOCALAPPDATA%\DonathonTimer\donathon.db` в резервную папку. Не запускай одновременно старую и новую версии: обе используют один локальный порт OBS (`127.0.0.1:17321`).

Удаление через Windows «Установленные приложения» не удаляет базу и настройки. В portable-версии база хранится там же, поэтому portable тоже использует текущий профиль.

## Важные ограничения бета-версии

- Исполняемые файлы создаются на Windows; архив исходников **не является готовым Setup.exe**.
- Бета пока не подписана сертификатом разработчика; SmartScreen может предупреждать о неизвестном издателе. Проверяй источник и SHA-256, не отключай защиту системы.
- GitHub Releases нужно сделать общедоступным, иначе друзья не смогут скачать файлы без доступа к репозиторию.
- Первой модели речи нужен отдельный доступ в интернет (она загружается библиотекой из сервиса моделей).
- Возможны зависимости от установленного Microsoft Visual C++ Redistributable; если на чистой машине worker не запускается, проверь этот компонент.
- Сборку и её установку необходимо проверить на Windows до раздачи тестерам. Синтаксическая проверка кода на Linux не заменяет тест живого Setup.exe.
